## 1. 摘要（Summary）

ChemAI（智辅化学）是一套面向高中化学教学的 AI 助教系统，包含**教师端、学生端、家长端**三个客户端，共用同一个 AI 内核。它不做搜题、不做题库，只回答一个现有产品都不回答的问题：**这个学生为什么错**。通过"拍照上传答题卡 → 自动诊断错因 → 生成讲评重点与练习建议"，把老师考后 6–10 小时的重复统计压缩到可依赖的诊断报告（该时长口径为**示例假设，未验证**），让学生知道"错在哪、下一步练什么"，让家长"看得懂进步、不排名"。

## 3. 背景（Background）

### 3.1 这件事是什么

高中化学老师每次考试后要做大量**重复性错因统计**：翻卷、分类、手写"正"字、做 Excel。这些时间本应用于真正需要专业能力的"个性化讲评"。

### 3.2 为什么是现在

- **政策窗口**：2021 年"双减"后学习质量需求从校外转向校内；2023–2025 年教育部密集出台政策（《基础教育课程教学改革深化行动方案》《中小学生成式人工智能使用指南（2025年版）》），明确鼓励用 AI 辅助教学分析。
- **需求真实存在（公开来源，未独立核实）**：教育部《中小学教师负担情况调查问卷》(2023) 显示教师周均工作 **54.6 小时**，"学习评分"是教师最期待减轻的负担之一（**53%**）；《中国教育学刊》2023 年对 48,874 名教师的调研显示 **72.5%** 教师日均工作超 8 小时。
- **技术刚刚可行**：大模型具备了化学推理与"分步骤判断"能力——**这是"诊断"（而非"统计"）第一次在成本上变得可行**。

### 3.3 现有产品的空白

| 现有产品 | 给的是 | 缺的是 |
|----------|--------|--------|
| 阅卷系统 | 统计（"全班 35% 错了"） | 为什么错 |
| 搜题工具 | 答案（"这题选 B"） | 为什么错 |
| 题库 | 试卷下载 | 为什么错 |

**没有人回答"这个学生为什么错"。**

## 4. 目标（Objective）

### 4.1 目标是什么

让每一位化学老师都有一个不知疲倦的 AI 助教，让每一个学生的错题都能被真正"读懂"。

### 4.2 为什么重要

- **对客户**：老师把时间还给教研；学生从"盲目刷题"转为"针对性补救"；家长从"不知道怎么办"变为"知道关注什么"。
- **对公司**：诊断是整条价值链的起点——没有诊断，练习、报告、家长触达全是空的。谁掌握"诊断"，谁就掌握 B2B2C 的入口。
- **与战略对齐**：对应三大战略主题——A 老师离不开（效率+信任）/ B 学生真进步（诊断+自适应）/ C 家长看得见（透明+安心）。

### 4.3 关键结果（SMART / OKR，均为设计目标，未验证）

**O1：在 3 所种子学校建立可信赖的口碑**
- KR1 种子老师周活跃率 ≥ 80%
- KR2 OCR→报告全流程 ≤ 15 分钟/班（90 人）
- KR3 教师 NPS ≥ +30

**O2：把错因诊断准确率提升到可依赖水平**
- KR1 障碍分类与资深老师一致率 ≥ 80%
- KR2 方程式配平审核准确率 = 100%（零误差红线）
- KR3 AI 生成题通过四维审核比例 ≥ 95%

**O3：建立家长"每周必看"的学情报告习惯**
- KR1 家长周报打开率 ≥ 50%
- KR2 家长端 MAU ≥ 50
- KR3 报告"有帮助"反馈率 ≥ 60%

**北极星指标**：每月诊断的错题数（MDEI）——种子期目标 5,000–10,000/月（设计目标，未验证）。口径见 `14-北极星指标.md`。

## 5. 市场细分（Market Segment(s)）

> 市场由"人们的待办任务（JTBD）"定义，而非人口属性。

| 细分 | 他们想完成的任务（JTBD） | 关键约束 |
|------|--------------------------|----------|
| **化学教师**（核心） | 考后快速得出"全班错因归类 + 讲评重点排序"，只讲该讲的题 | 上手要快；采购走学校流程；不信任 AI 就不留存 |
| **选考化学学生** | 知道"我为什么错、下一步练什么"，而不是只看到分数 | 只看自己的数据；不能被直接给答案；要看到进步而非只有错 |
| **学生家长** | 看懂孩子的学习状态，知道该关注什么 | 不排名（价值观硬约束）；语言要通俗 |

**约束清单**：① 化学内容零安全事故；② 学生 PII 不外流；③ 强监管（教育备案/未成年人保护）；④ 教师端不做"指令化"自动化。

## 6. 价值主张（Value Proposition(s)）

### 6.1 化学教师

- **要完成的任务**：考后完成全班错题统计、错因归类、讲评重点排序。
- **能获得**：OCR 自动统计 + 障碍类型诊断 + 讲评优先级建议；新手老师也能精准讲评。
- **能避免的痛**：摆脱手写"正"字与机械对答案；不再"凭感觉"讲评。
- **比竞品好在哪**：唯一做"化学学科专属错因诊断"（概念/审题/表达），而非通用阅卷。

### 6.2 学生

- **任务**：知道"我为什么错、下一步练什么"。
- **获得**：个人错因报告（第一屏是进步）+ "最近发展区"自适应练习。
- **避免的痛**：不再只有红叉和分数；不再"会的反复做、不会的还是不会"。

### 6.3 家长

- **任务**：看懂孩子学习状态、知道该关注什么。
- **获得**：每周通俗学情简报 + 可操作建议。
- **避免的痛**：不再"不知道怎么办"的焦虑；**始终不排名**，不制造攀比。

### 6.4 价值曲线（相对竞品的差异化）

| 价值要素 | 阅卷系统 | 搜题工具 | 题库 | **ChemAI** |
|----------|:--:|:--:|:--:|:--:|
| 统计正确率 | 高 | 低 | 低 | 高 |
| 错因诊断 | 低 | 低 | 无 | **高** |
| 自适应练习 | 无 | 中 | 中 | 高 |
| 家长视角（不排名） | 无 | 无 | 无 | **高** |
| 直接给答案 | — | 高 | 高 | **不做**（刻意的反向选择） |
| 讲评优先级的"建议" | 无 | 无 | 无 | **高** |

> 差异化不在"功能更多"，而在**把重心放在错因诊断**，并**刻意不做"直接给答案"和"排名"**——这两条"不做"本身就是价值主张。

## 7. 方案（Solution）

### 7.1 UX / 原型

- **信息架构**：三端独立界面，共用 Agent 内核。教师端=考试工作台（上传→报告→诊断→仪表盘）；学生端=我的报告 + 练习；家长端=周报 + 深度报告。
- **可运行原型**：已完成三端网页 + REST 接口（`app/`，线上可访问），含快捷提问、工具调用轨迹可视化、护栏状态显示。
- **页面线框与交互思路**：详见 `ChemAI-完整产品文档/第五部分-工程实现/21-原型验证与POC.md`。
- **核心用户流程**：见同目录 `flows.md`（F-A 教师上传→诊断、F-B 学生诊断→练习、F-C 家长周报、F-D Agent 对话、F-E AI 出题审核）。

### 7.2 关键功能

| 模块 | 功能 | 解决的 JTBD |
|------|------|-------------|
| F1 | OCR 答题卡识别 | 取代手写统计 |
| F2 | 四维化学安全审核 | 内容安全红线 |
| F3 | 双层错误报告（教师版/学生版） | 一份数据、两种视角 |
| **F4** | **障碍类型诊断** | **核心差异化：为什么错** |
| F5 | 自适应练习 | 知道错后练什么 |
| F6 | 历史真题关联 | 讲评时说"高考这么考过" |
| F7 | 班级学情仪表盘 | 备课组长定位年级薄弱点 |
| M1/M2 | 认证权限、学校班级 | 四角色数据隔离 |
| M16/M17 | 家长端、通知推送 | B2B2C 闭环 |

> 完整功能需求（FR-01~24）+ Given/When/Then 验收见 `PRD.md` 第七章；功能优先级（ICE/RICE/Kano）见 `18-功能优先级排序.md`。

### 7.3 技术（概述）

- **Agent 架构**：单 Agent（LangGraph）+ 22 个化学工具 + **Persona 四角色隔离** + 三层记忆。
- **三端隔离**：靠**代码层硬过滤**（工具注册表声明每个工具的可用端别），不靠 prompt 约束。
- **质量防线**：14 维度评测体系（确定性层 + API 层两层）+ 硬/软分级护栏。
- **技术栈**：FastAPI / SQLite / ChromaDB（规划）；原型为纯标准库自包含实现。
- 详见 `ChemAI-完整产品文档/第五部分-工程实现/26-架构决策记录.md`、`23-Prompt工程与Agent行为设计.md`。

### 7.4 假设（尚未验证，须由种子期验证）

| # | 假设 | 验证方式 |
|---|------|----------|
| A1 | 化学老师愿意为 AI 诊断改变工作流 | 种子期教师访谈 + 周活跃率 |
| A2 | 老师不需要全自动讲评 PPT，只要带优先级的分析报告 | 教师访谈（V10 洞察） |
| A3 | AI 诊断与资深老师判断一致率可达 ≥80% | 双盲对照评测 |
| A4 | 学生"不知道自己为什么错"是真痛点 | 学生访谈/问卷 |
| A5 | 家长更在意"进步"而非"排名" | 家长访谈/问卷 |
| A6 | 家长愿为深度报告付费（转化 ≥8%） | 付费漏斗（Phase 2） |

## 8. 发布（Release）

> 用相对时间，避免锁死具体日期。

### 8.1 总体节奏

| 阶段 | 相对时间 | 主题 | 退出条件 |
|------|----------|------|----------|
| **Phase 1 种子验证** | 首个季度 | 证明 3 个假设（老师愿用、诊断可信、闭环通） | Gate 1 Go/No-Go |
| **Phase 2 规模化** | 第 2–3 季度 | 从 3 所扩展到 20 所，验证可复制性 | 转介绍率 ≥40% |
| **Phase 3 品类领导者** | 第 4–6 季度 | 成为化学教学基础设施 | 知识图谱全覆盖 |

### 8.2 第一版（v1 / MVP）包含什么

F1 OCR + F2 审核 + F3 双层报告 + F4 障碍诊断 + F5 自适应练习 + F6 真题关联 + F7 仪表盘；底座 M1/M2/M5/M6/M7/M16/M17。

### 8.3 第一版**不**包含什么

排名功能（价值观禁止）、全自动讲评 PPT、M18 LMS 集成、M15 校级看板、M21 MCP、M25 浏览器自动化。

### 8.4 每版必修项

- **资金/支付**（家长付费）：上线前必须补齐资金三件套（幂等 + 对账 + 资损监控）。
- **数据能力**：每个版本至少 1 个核心指标看板（本周 MDEI + 诊断采纳率 + 单班处理时长），禁止无数据可复盘。
- **安全**：四维审核与"不排名"每次发布前必须过安全测试（安全事故 = 0）。
