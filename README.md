# ChemAI · 智辅化学

> 面向高中化学教学的 AI 错因诊断原型：从题干与学生作答出发，探索生成附带作答依据和追问的错因假设，供教师复核。

**个人独立项目 · AI 产品经理作品集**  
项目覆盖：问题定义、需求拆解、产品设计、Agent 原型、Prompt 评测与迭代。

**当前阶段：可运行原型与小样本实验。** 尚未完成真实用户访谈、学校试点或教学效果验证。

**在线演示：** [ChemAI 化学学习助手](https://chemai-study-demo.sleepearly26.chatgpt.site)。此演示版部署在 Worker 环境；对话依赖服务端 API 配置，会话和演示额度状态保存在运行实例内存中，不用于真实学生数据或生产教学。

## 1. 为什么做这个项目

判定一道题“对或错”之后，教师还需要判断学生在哪一步产生了偏差，才能组织讲评和后续练习。ChemAI 围绕这一场景，探索如何用 AI 辅助分析概念、审题和表达等可能的错误原因。

**核心假设**：带有学生作答依据、能说明不确定性的诊断建议，可以帮助教师形成更有针对性的讲评。这一价值判断仍需真实教师验证，目前不宣称已节省工时或提升成绩。

产品将大模型用于理解非标准作答、生成候选解释与追问；最终教学判断由教师完成。提示词要求信息不足时优先请求补充过程，避免将猜测写成确定结论；实际遵循情况通过评测观察。

## 2. 原型做到了什么

| 场景 | 产品设计 | 当前实现边界 |
|---|---|---|
| 教师端 | 引用作答依据，给出错因假设与讲评建议 | 支持文本对话与内置样例，未接入真实答题卡 OCR |
| 学生端 | 通过提问引导思考，限制直接给答案 | 已配置角色提示词与工具边界，不能保证所有输入下均不越界 |
| 家长端 | 通俗解释学习情况，限制排名类输出 | 已实现角色化对话；档案工具使用示例数据，班级概览工具仅向教师端开放 |

原型包含三端网页、REST 接口、角色路由、工具调用、**最近 4 轮对话上下文**、关键词知识库检索、输出风险标记与请求额度限制。服务使用 **Python 标准库**实现。

**实现边界**：最近对话上下文按会话和角色隔离，每个会话最多保留 8 条消息、每次最多带入 12,000 字符；会话只保存在内存，服务重启后丢失。工具调用有角色权限检查，但角色选择和会话 ID 都不等于身份鉴权；输出护栏只标记风险，仍返回原回答，尚未实现违规内容阻断。

OCR、确定性化学方程式校验、真实班级数据、完整身份鉴权及教学反馈闭环属于后续规划。附录中的更完整技术架构也属于目标方案。

### 如何演示

1. 在教师端选取内置样例，查看“关键差异—错因假设—需要补充的信息—讲评建议”。
2. 在同一端分两轮输入：先贴出题目和作答，再补充解题步骤，观察 AI 是否结合前文继续分析。
3. 切换家长端，观察语言表达与排名限制。
4. 对照评测中的失败案例，解释哪些输出还需要人工复核。

## 3. 我负责的工作与关键取舍

本项目由个人独立推进，覆盖问题与场景定义、需求和交互设计、可运行原型及评测材料的组织。文档撰写与交叉校验使用了 AI 辅助；个人项目不代表已有学校合作或团队交付经历。

| 产品决策 | 选择与理由 |
|---|---|
| 缩小验证范围 | 以文本错因分析与有限对话上下文为当前验证入口，OCR 与教学闭环列为后续规划 |
| 保留教师判断 | 让模型输出假设、依据与追问，避免直接下学生能力或态度结论 |
| 区分三端需求 | 教师侧辅助复核，学生侧引导思考，家长侧解释学习情况 |
| 拆开质量指标 | 分别观察规则合规、裁判判断与响应延迟，避免用单个通过率代替产品质量 |

## 4. 评测证据：v1 → v2

使用 **15 条自建样例**，v1、v2 各重复运行 3 轮，每版累计 45 次输出。重复运行用于观察波动，**不等于 45 条独立样本**。

v1 为刻意设置的宽松基线；v2 在教师端提示中明确证据引用、信息不足追问和固定结构要求。两版都由 Agent 追加角色规则与工具协议，因此 v1 不是完全无约束的模型。

**实验条件**：评测输入包含题目、参考答案、学生作答和预先标注的歧义类型。这验证的是已提供参考信息下的辅助分析，不能据此证明模型能独立发现信息缺失。v1 未被要求使用四段结构，因此结构指标的提升主要说明新增格式要求得到遵循，不能单独作为诊断能力提升的证据。

| 指标 | v1 | v2 |
|---|---:|---:|
| 四个指定小节关键词齐全率 | 0/45（0%） | 45/45（100%） |
| 输出含引号比例（引用代理信号） | 41/45（91.1%） | 45/45（100%） |
| 缺信息子集中追问关键词命中率 | 9/12（75%） | 12/12（100%） |
| LLM 裁判通过率 | 82.2% | 88.9% |
| 平均模型调用累计耗时 | 2.04 秒 | 3.59 秒 |

**结果解读**：在这组样例中，v2 更稳定地满足预设输出要求，但模型调用耗时也增加。规则只检测小节关键词、引号和追问关键词，未验证引用是否确实来自学生原文，也未验证追问是否有效。LLM 裁判通过率为 37/45 → 40/45，尚无教师人工金标准支持准确率结论。这些历史单轮评测没有覆盖新加入的多轮上下文功能。耗时为每条样例内模型调用时间之和，不含裁判、前端和完整服务处理时间。

## 5. 迭代复盘与下一步

**已观察到的问题**：v2 报告中仍有 C03、C09 等未通过项，涉及缺条件判断、等价表述与证据使用。应同时检查模型原始输出和裁判理由，不能把所有失败都归咎于模型，也不能一概解释为裁判误判。

**本轮观察**：更明确的提示约束伴随着更稳定的输出形式和更长的模型调用耗时；尚未通过独立测试集验证这一变化是否能泛化。对教师是否更有帮助、等待时间是否可接受，还需要实际体验反馈。

**下一步按优先级验证**：

1. 邀请少量高中化学教师完成访谈和样例试用，记录当前做法、复核耗时、采纳与驳回原因。
2. 扩充独立评测样例，增加正确作答、缺失过程、等价表述及诱导越界情形；区分调试样例与留出测试样例，并增加不提供歧义标签的对照实验。
3. 引入教师人工复核，分别衡量化学正确性、证据充分性与建议可用性，再决定功能扩展。

以上均为待执行计划；目前不报告用户增长、付费转化、工时节省或成绩提升成果。
